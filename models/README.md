# Models

Model blobs are local runtime artifacts. They are ignored by git because they
can be regenerated or imported from local model checkouts. Runtime paths use
`.bin` files so the visualizer has one consistent binary-model convention.

Populate or refresh the default files with:

```sh
./scripts/import_models.sh
```

The importer checks, in order:

```text
$MODEL_SOURCE_DIR
~/Code/chess-models/models
~/Code/chess-rtk/models
```

If no local source exists and a known generated fallback is available, the
script creates the compact model locally. Set `MODEL_IMPORT_MODE=symlink` to
link local files instead of copying them. Set `FORCE=1` to replace existing
files.

## Default Runtime Files

| File | Approx. size | Loaded by | Purpose |
| --- | ---: | --- | --- |
| `nnue-halfkp-demo.bin` | 2.6 MB | `model.nnue` | Compact deterministic HalfKP/NNUE float model. |
| `lc0-cnn-small-112p-4x32-policy4672-wdl3.bin` | 0.7 MB | `model.lc0_cnn` | Compact LC0J CNN model with 112 planes, 4 residual blocks, 32 trunk channels, 4672 policy logits, and WDL head. |
| `lc0-bt4-tiny-96x4x4h.bin` | 1.9 MB | `model.lc0_bt4` | Compact real BT4J v2 transformer with 96-dimensional tokens, 4 encoder blocks, 4 heads, attention policy, and WDL head. |

Optional larger local files may also be present for experiments, for example
`lc0-cnn-112p-10x128-policy4672-wdl3.bin` or
`lc0-bt4-small-128x6x8h.bin`. They are not the default runtime files.

## NNUE Format

Little-endian. All tensor payloads are `float32`.

```text
"NNUE"                          (4 bytes)
uint32  version                 == 1
uint32  featureCount            == 40960
uint32  hiddenSize              H
float32 outputScale
uint32  N0 + N0 * float32       featureBias     (N0 == H)
uint32  N1 + N1 * float32       featureWeights  (N1 == featureCount * H)
uint32  N2 + N2 * float32       outputWeights   (N2 == 2 * H)
float32 outputBias
```

The feature count is `64 * 10 * 64`: king square, ten non-king piece planes,
and piece square.

## LC0J CNN Format

Little-endian. Generated by `scripts/generate_small_cnn.py` and loaded by
`src/nn/lc0_cnn/Lc0CnnLoader.cpp`.

Header:

```text
"LC0J"                          (4 bytes)
uint32  version                 == 1
uint32  inputChannels           == 112
uint32  trunkChannels
uint32  residualBlocks
uint32  policyChannels
uint32  valueChannels
uint32  valueHidden
uint32  policyMapLength
uint32  wdlOutputs              == 3
```

Payload:

```text
conv stem
residualBlocks * (conv1, conv2, seFlag/optional se)
policy stem conv
policy output conv
value conv
value fc1
value fc2
policyMapLength * int32 policy map entries
```

The default small CNN uses the real native CNN forward pass. Its weights are
freshly initialized, so it is a visualization model rather than a strong chess
engine.

## BT4J Transformer Format

Little-endian. Generated by `scripts/generate_small_bt4.py` and loaded by
`src/nn/lc0_bt4/Bt4BinLoader.cpp`.

The file starts with:

```text
"BT4J"                          (4 bytes)
uint32  version                 == 2
string  architecture name
string  input format            e.g. BT4_CANONICAL_112
string  input embedding mode
int32   inputChannels
int32   tokens
int32   embeddingSize
int32   encoderLayers
int32   attentionHeads
int32   policySize
float32 layerNormEpsilon
int32   ffnHiddenSize
int32   smolgenHiddenChannels
int32   smolgenHiddenSize
int32   smolgenPerHeadDim
int32   smolgenGlobalSize
string  default activation
string  smolgen activation
string  ffn activation
bool    hasInputPreproc
bool    hasInputEmbFfn
bool    hasInputGates
bool    hasSmolgen
```

The remaining payload mirrors the CRTK BT4J v2 nested records:

- input stack,
- encoder blocks,
- optional shared smolgen projection,
- attention policy head,
- WDL value head.

The default tiny BT4J file intentionally disables smolgen, input preproc,
input gates, and embedding FFN to keep the artifact small. The loader and
forward structs support those records when present.

## Legacy BT4V Fallback Metadata

`Bt4Network` still accepts the older `BT4V` metadata-only format:

```text
"BT4V"                          (4 bytes)
uint32  version                 == 1
uint32  inputChannels           == 112
uint32  tokens                  == 64
uint32  tokenWidth              == 176
uint32  modelDim                == 64
uint32  blocks                  == 15
uint32  heads                   == 8
uint32  policySize              == 1858
uint32  seed                    reserved deterministic visual seed
```

That path validates dimensions and uses deterministic synthetic activations.
The current default model is the real `BT4J` path, not `BT4V`.
